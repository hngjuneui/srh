# 실행 검증 기록

검증 환경: 이 작업 PC / Windows / Python 3.12 / CPU MediaPipe / Chrome headless. 실제 휴대폰, 통신사망, 경기 영상은 사용하지 않았습니다.

## 통과

- Python `unittest`: **15개 통과**.
- 실제 MediaPipe 모델 로드 및 빈 영상 추론: 오류 없음.
- WebSocket의 프레임 ID 왕복, 서버 JPEG 수신 확인.
- 파일 업로드 → H.264 재생본 변환 → PC 분석 → 구간 수정 → MP4 합치기.
- 두 구간의 출력 길이 검증: 1.4초, 허용 오차 0.2초 이내.
- 합성 관절 시계열: 랠리 종료 → 시험 자동 득점 → 양팔 X로 득점 이전.
- 4개 포즈 각각 X 입력, 중복 차단, 인물 누락·수신 공백·랠리 중 차단.
- 듀스, 상한, 게임·경기 종료, 직전 득점 수정 후 서브/게임 승패 재계산.
- 알고리즘 비활성, 충돌, 같은 종류의 상관 신호를 독립 근거로 세지 않는 로직.
- Chrome UI: 로그인, 점수 수정/복원, 옵션 저장, 가상 카메라 전송, 파일 업로드, 이어보기, MP4 다운로드.
- 1440px 데스크톱과 390px 모바일 레이아웃 확인. 검사한 모바일 화면에서 가로 넘침 없음.
- 브라우저 JavaScript 오류: **0개**.
- JavaScript 구문 검사와 `pip check` 통과.

가상 카메라의 한 측정 스냅샷: 왕복+분석 38ms, PC 처리 32ms, 수신 7.9fps, 업로드 0.54Mbps. 단순 합성 영상 및 localhost에서의 값으로, 실제 4인 배드민턴이나 LTE/5G 성능 예측에 사용할 수 없습니다.

## 발견 후 수정한 문제

- OpenCV로 분석되는 MPEG-4 파일이 Chrome에서는 재생되지 않음 → 업로드 원본을 보존하며 H.264/AAC 재생본 생성.
- 준비 중 첫 두 응답으로 계산한 fps가 일시적으로 과대 표시됨 → 최소 1초 측정 후 표시.
- 복수 영상 분석 작업이 라이브 프레임 처리를 막을 수 있음 → 실시간/파일/내보내기 작업 실행기를 분리.
- 모바일 점수판이 영상 아래에 위치함 → 자동 스코어 모드에서는 점수판을 먼저 표시.
- 모델 종료 시 Python 정리 순서 오류 → 명시적 종료 처리.

## 미검증 또는 미구현

- 외부 HTTPS 주소, 실제 이동통신 연결, 장시간 녹화·배터리·발열·백그라운드 동작.
- 실제 경기의 득점, 랠리 경계, 네 사람의 X 동작 인식 정확도.
- 셔틀·라켓 접촉과 클리어의 정확한 타점, 품질 평가용 학습 모델.
- WebRTC/TURN 전송, 실시간 원본의 서버 녹화 및 끊김 후 자동 보충.

스크린샷과 합성 입력/출력 영상은 `test-results/`에 있으며 Git에서 제외됩니다. 테스트는 새로운 경기 세션과 별도 임시 디렉터리를 사용합니다.
